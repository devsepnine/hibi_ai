# npm 의존성 업데이트

npm 의존성 버전을 확인하거나 패키지를 업데이트할 때 사용한다. 버전 확인 요청에는 조사 결과를 전달한다. 업데이트 요청에는 아래 준비 및 검증 절차를 따른다.

## 업데이트 범위 정하기

1. npm 프로젝트 루트와 영향을 받는 매니페스트를 찾는다. 프로젝트가 명시한 Node와 npm 버전, 레지스트리 설정, 잠금 파일 정책을 따른다. npm workspace라면 대상 패키지와 공유 잠금 파일을 확인한다. 프로젝트가 다른 패키지 관리자를 지정하면 해당 도구의 절차를 따른다.
2. 대상 매니페스트와 실제로 사용하는 잠금 파일을 읽는다. 선택한 직접 의존성별 선언 범위와 설치 버전 또는 잠금 파일 버전을 기록한다. 설치 버전과 잠금 파일 버전을 구분한다. 둘 다 확인할 수 없으면 미확인으로 표시한다.
3. 선택한 패키지의 레지스트리 버전을 확인한다. `npm outdated --json`으로 조사를 시작한다. 최신화할 패키지를 찾아 npm이 종료 코드 1을 반환한 경우에도 JSON 결과를 읽는다. 가장 높은 안정 버전을 확인할 때는 `npm view "$package" versions --json`으로 배포 버전 목록을 읽는다. SemVer 기준으로 비교하고 사용자가 요청한 경우에만 프리릴리스 버전을 포함한다. 조회가 실패하면 해당 패키지와 오류를 알린다.
4. 제안하는 버전, 기존 선언 범위에 들어가는지 여부, 알려진 호환성 문제를 보여준다. 변경이 프로젝트 동작에 영향을 줄 수 있으면 릴리스 노트와 실제 사용처를 확인한다. 정확한 버전으로 고정한 의존성과 레지스트리 외부 소스는 사용자가 변경을 요청할 때만 바꾼다. 일괄 업데이트에 major 변경을 포함할지처럼 요청에서 범위가 모호한 부분만 확인한다.

## 격리된 복사본에서 준비하고 검증하기

1. 현재 프로젝트 파일에서 시작해 기존 편집을 기준 상태에 포함한다. 비공개 임시 복사본에 별도 `node_modules`를 사용한다. workspace 구조를 유지하고 로컬 의존성도 복사본 안에서 찾을 수 있게 한다. 구조나 필수 입력을 재현할 수 없으면 원래 프로젝트에 반영하기 전에 이유를 알린다. 대상 의존성 파일의 기준 상태를 별도로 보관하고, 작업 전 파일이 없었던 경우도 기록한다.
2. 선택한 업데이트의 버전을 결정하고 의존성 코드를 실행하기 전에 매니페스트와 잠금 파일의 diff를 검토한다. 이 단계의 npm 명령에 `--ignore-scripts`를 사용한다. 잠금 파일만 준비하고 명령이 지원하면 `--package-lock-only`도 사용한다. 결정된 버전과 의존성 분류, 범위와 고정 버전을 확인한다. 선택한 업데이트에 필요한 잠금 파일 변경만 남기고, 범위 밖 직접 의존성이 바뀌면 그 차이를 정리한다.
3. 프로젝트가 사용하는 설치 절차와 관련 테스트나 빌드를 검증한다. 호환되는 잠금 파일로 깨끗하게 설치하는 프로젝트는 `npm ci`를 사용한다. 임시 복사본은 실행 프로세스의 파일 시스템과 환경 변수 접근 권한을 공유한다. 신뢰할 수 없는 의존성 코드를 실행하는 검증은 원래 체크아웃, 비공개 파일과 자격 증명에 접근할 수 없는 일회용 샌드박스에서 실행한다. 비공개 레지스트리는 스크립트를 끈 상태에서 먼저 패키지를 받고, 준비한 캐시 등 필요한 패키지 데이터만 샌드박스에 전달한다. 레지스트리 토큰이나 자격 증명이 든 `.npmrc`는 전달하지 않는다. 필요한 격리 환경이 없으면 끝낸 검사 범위를 알려주고 변경 후보를 복사본에 보관한다. 설치나 검증에 실패하면 명령과 대상 패키지를 알리고 원래 프로젝트를 보존한다.

## 검증한 변경 반영하기

1. 기준 상태와 검증을 마친 복사본을 비교해 패치를 만든다. 선택한 매니페스트와 프로젝트가 유지하는 잠금 파일만 포함한다. 적용 직전에 원래 파일이 기준 상태와 같은지 확인한다. 그사이에 바뀌었다면 새 편집을 보존하고 최신 상태를 기준으로 후보를 다시 준비한다.
2. 패치를 검사한 뒤 한 번에 반영한다. 패치 경로는 체크아웃 루트를 기준으로 쓴다. Git 저장소 밖이라면 프로젝트 루트를 기준으로 쓴다. 적용 전에 대상 파일 목록을 확인한다. 반영 결과를 확인할 때까지 패치와 기준 상태를 보관한다.

   ```bash
   git -C "$patch_root" apply --check "$dependency_patch" &&
     git -C "$patch_root" apply "$dependency_patch"
   ```

3. 원래 체크아웃의 매니페스트와 잠금 파일을 읽고 검증한 복사본과 비교한다. 적용에 실패하면 실제 파일을 확인하고 반영된 변경이 있으면 알린다. 실패를 처리하는 동안 사용자의 편집을 보존한다.
4. 반영한 버전, 검증 결과, 건너뛴 패키지를 알린다. 의존성을 설치한 위치와, 원래 체크아웃에서도 설치된 패키지를 갱신해야 할 때 사용할 프로젝트의 설치 절차를 안내한다.
