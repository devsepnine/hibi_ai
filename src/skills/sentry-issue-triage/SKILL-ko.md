# Sentry 이슈 조사

사용 가능한 Sentry 커넥터나 설치된 Sentry 스킬로 이슈와 이벤트를 읽기 전용으로 조회한다. 로컬 저장소에 소스가 있으면 오류가 발생한 코드 경로를 추적한다.

1. 사용자가 준 이슈 링크나 ID, 또는 보고된 오류에서 시작한다. 요청에 해당하는 조직, 프로젝트, 환경, 릴리스, 조회 기간을 확인한다. 링크, 확인된 프로젝트 정보, 사용 가능한 필터를 활용한다. 정보가 부족해 다른 프로젝트나 환경을 조회할 수 있으면 먼저 묻는다.
2. 이슈 요약을 읽고 해당 범위에서 대표 이벤트를 고른다. 사용한 필터를 기록하고 이슈 집계 정보와 개별 이벤트에서 관찰한 내용을 구분한다. 오류 급증이나 회귀 여부를 조사할 때는 조회 결과가 비교 대상인 기간 또는 릴리스를 모두 포함하는지 확인한다. 조회 범위의 누락이나 표본 추출이 판단에 영향을 주면 밝힌다.
3. 예외 스택에서 오류와 관련된 첫 번째 애플리케이션 프레임을 찾는다. 확인 가능한 경우 심볼이 복원된 프레임과 릴리스 식별자를 사용한다. 프레임에 해당하는 저장소 파일과 코드 경로를 추적한다. 배포된 리비전이 로컬과 다르거나 연결이 확실하지 않으면 확인한 범위를 밝힌다. 원인 후보를 좁힐 수 있으면 브레드크럼과 주변 프레임을 살핀다.
4. 이슈 링크, 탐색 범위, 확인된 영향, 관련 프레임, 로컬 소스 위치를 보고한다. 확인한 사실과 추정 원인을 구분하고 추가로 필요한 증거를 명시한다. 인용은 민감한 부분을 가리고 인증 정보, 사용자 식별자, 요청 본문 등 비공개 이벤트 세부 사항은 생략한다.
5. 사용자가 코드 수정을 요청하면 확인한 코드 경로와 제안한 검증 방법을 저장소의 버그 수정 절차에 전달한다.
