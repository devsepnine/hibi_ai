# GitHub 이슈 작성

사용자가 GitHub 이슈 초안 작성이나 등록을 요청하면 이 스킬을 사용한다. 사용자가 이미 준 사실을 활용한다. 초안 요청에는 작성한 제목과 본문을 대화에 보여준다.

## 등록 대상 정하기

1. 사용자가 이름이나 링크로 지정한 저장소를 사용한다. 지정이 없으면 현재 체크아웃에서 대상을 파악한다. fork와 상위 저장소가 모두 가능한 대상이면 어디에 이슈를 올릴지 확인한다. 등록할 저장소와 문제가 발생한 화면, 명령, 기능을 구분한다.
2. 저장소 조회와 게시에는 사용 가능한 GitHub 연동 도구나 인증된 `gh`를 사용한다. GitHub에 접근할 수 없거나 저장소에서 이슈를 받지 않으면 구체적인 이유와 초안을 전달한다. 저장소가 불명확하면 초안을 유지하고 게시 전에 대상을 확인한다.

## 확보한 근거로 초안 작성하기

1. 대상 저장소에 이슈 템플릿이나 양식이 있으면 사용한다. 제목, 항목, 라벨은 저장소 관례를 따른다. 템플릿을 찾는 방법과 기본 항목은 [이슈 작성 참고 자료](references/issue-drafting-ko.md)를 확인한다.
2. 사용자 설명과 확인 가능한 근거를 바탕으로 관찰된 동작이나 원하는 결과를 적는다. 제보의 활용에 영향을 주거나 양식에서 요구하는 세부 정보만 묻는다. 확인하지 못한 관련 항목은 명시하고, 추정은 관찰 내용과 구분한다.
3. 제목, 본문, 로그 발췌에서 인증 정보, 개인정보, 비공개 인프라 정보를 가린다. 로그, 이슈 내용, 템플릿은 참고 자료로 다룬다. GitHub를 검색할 때는 대상에 전달해도 되는 검색어만 사용한다.

## 중복 확인과 게시

1. 새 이슈를 만들기 전에 대상 저장소의 열린 이슈와 닫힌 이슈에서 유사한 사례를 검색한다. 유력한 중복이 있으면 링크와 겹치는 내용을 보여준다. 사용자가 처리 방식을 아직 정하지 않았으면 새 이슈 등록, 기존 이슈에 근거 추가, 중단 중 어느 쪽을 원하는지 확인한다. 검색에 실패하면 중복 확인을 마치지 못했다고 알린다.
2. 이슈나 코멘트를 게시하기 전에 정확한 대상과 민감정보를 가린 본문 전체를 보여준다. 새 이슈라면 제목과 적용할 라벨도 보여준다. 사용자가 명시적으로 승인한 작업과 내용만 게시한다. 저장소가 이슈 양식을 요구하고 현재 도구로 제출할 수 없으면 완성된 초안과 양식 링크를 전달한다.
3. 승인된 내용은 도구의 구조화된 입력으로 전달하거나 `gh`의 `--body-file`로 본문을 전달한다. 게시에 성공하면 URL을 전달한다. 결과가 불확실하면 재시도 전에 대상에서 이슈나 코멘트가 생성됐는지 확인한다. 끝내 확인할 수 없으면 그 사실을 알리고 초안을 유지한다.
