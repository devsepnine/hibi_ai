# Git worktree 관리

사용자가 worktree를 요청하거나 작업에 별도 체크아웃이 필요할 때 이 스킬을 사용한다. 기존 체크아웃에 있는 변경을 이어가거나 커밋하는 작업이면, 사용자가 격리를 요청한 경우를 제외하고 그 체크아웃을 사용한다.

## 저장소와 브랜치 확인하기

1. 사용자가 지정한 저장소를 사용한다. 지정이 없으면 현재 저장소를 사용한다. `git rev-parse --show-toplevel`로 체크아웃의 루트 경로를 확인한다. bare 저장소라면 Git 디렉터리를 사용한다. 작업 경로를 정하기 전에 `git worktree list --porcelain`을 읽는다. 첫 레코드는 메인 worktree 또는 bare 저장소를 가리킨다. 코드로 출력을 파싱할 때는 `-z`를 사용한다.
2. 사용자가 요청한 브랜치 이름을 사용하거나 저장소 관례에 맞는 이름을 고른다. `git check-ref-format --branch`로 검사하고 출력값이 입력한 이름과 같은지 확인한다. worktree 목록에서 전체 `refs/heads/<branch>`가 일치하는 항목을 찾는다. 등록된 체크아웃에 접근할 수 있고 실제 브랜치가 일치하는지 확인한 뒤 재사용한다. 상태를 확인하고 기존 수정은 보존한다.
3. 격리가 필요한데 요청한 브랜치가 메인 worktree에서 사용 중이면 기존 경로를 보여주고 별도 작업 브랜치를 확인한다. 기존 linked worktree의 경로가 사용자가 지정한 경로와 다르면 두 경로를 보여주고 어느 쪽을 사용할지 묻는다. detached worktree나 접근할 수 없는 등록은 별도로 다룬다. 그대로 두고 요청을 막는 충돌이 있으면 원인을 설명한다.

## 필요할 때만 생성하기

1. 로컬 브랜치가 있으면 해당 브랜치의 끝 커밋을 사용한다. 사용자가 지정한 시작점과 다르면 진행 전에 확인한다. 브랜치가 원격에만 있고 그 작업을 이어가는 요청이면 해당 원격 브랜치를 사용한다. 여러 원격의 끝 커밋이 다르고 어느 쪽을 이어갈지 모호하면 확인한다.
2. 새 작업 브랜치는 사용자가 지정한 시작점을 우선한다. 지정이 없으면 저장소가 문서에 명시한 기준이나 선택한 원격의 기본 브랜치를 사용한다. 정확한 ref를 커밋으로 확인한다. 기준이 모호하면 worktree를 만들기 전에 확인한다. 원격 최신 커밋이 필요하면 커밋을 확인하기 전에 fetch한다. fetch에 실패하면 오류를 알리고 사용 가능한 로컬 ref로 진행해도 되는지 확인한다.
3. 사용자가 지정한 경로나 저장소의 worktree 위치를 사용한다. 둘 다 없으면 메인 worktree나 bare 저장소와 같은 상위 디렉터리에서 사용 중인 항목이 없는 경로를 고른다. 체크아웃 내부에 둘 때는 Git이 무시하는 위치를 사용한다. 후보 경로에 다른 체크아웃이나 파일이 있으면 보존한다. 직접 고른 경로면 사용 중인 항목이 없는 경로를 새로 선택하고, 사용자가 지정한 경로면 확인한다.
4. 생성 전에 경로가 worktree 목록에 없고 아래 첫 번째 검사도 통과하는지 확인한다. 그다음 해당하는 생성 명령 하나를 실행한다. `repo`와 `worktree_path`는 절대 경로다. `branch`는 짧은 로컬 브랜치 이름이다. 원격 브랜치를 이어갈 때는 `tracking_ref`에 원격 추적 ref의 전체 이름을 넣고 생성 직전에 끝 커밋을 확인한다. 새 작업 브랜치를 만들 때는 확인한 시작 커밋을 `start_commit`에 넣는다.

   ```bash
   # 기존 파일과 디렉터리, 대상이 없는 심볼릭 링크를 확인한다
   test ! -e "$worktree_path" && test ! -L "$worktree_path"

   # 기존 로컬 브랜치를 체크아웃한다
   git -C "$repo" worktree add -- "$worktree_path" "$branch"

   # upstream을 설정해 원격 브랜치의 작업을 이어간다
   git -C "$repo" worktree add --track -b "$branch" -- "$worktree_path" "$tracking_ref"

   # 선택한 커밋에서 새 작업 브랜치를 만든다
   git -C "$repo" worktree add -b "$branch" -- "$worktree_path" "$start_commit"
   ```

## 체크아웃 확인하고 사용하기

- 명령의 성공 여부를 확인한다. 저장소의 worktree 목록에서 경로와 브랜치를 확인하고, 해당 체크아웃에서도 현재 브랜치를 확인한다. 생성에 실패하면 Git 오류를 전달하고 worktree 목록과 로컬 브랜치 ref를 다시 확인한다. 체크아웃에 실패해도 브랜치가 남을 수 있다. 남은 브랜치는 보존하고 사용자에게 알린다. 동시에 실행된 작업이 대상 체크아웃을 만들었다면 검증한 뒤 재사용한다.
- 원격 브랜치를 이어가는 경우 `HEAD`가 기록한 시작점과 일치하고 `git rev-parse --symbolic-full-name '@{upstream}'`의 결과가 `tracking_ref`와 일치하는지 확인한다. 하나라도 다르거나 조회할 수 없으면 차이를 알리고 체크아웃을 그대로 둔 채 작업을 보류한다.
- 작업을 이어갈 호출자에게 절대 경로와 브랜치를 전달한다. 새 worktree라면 시작점도 전달한다. 이후 편집, Git 명령, 빌드, 테스트는 그 경로에서 진행한다. 초기 설정이 필요하면 그 체크아웃에서 저장소 지침을 따른다.
- 기존 worktree와 브랜치를 보존한다. 사용하지 않는 경로의 등록이 진행을 막으면 그 경로를 알려 사용자가 처리 방법을 결정할 수 있게 한다.
