# Obsidian 볼트 관리

## Git 추적 범위 결정

1. 볼트 루트, Git 루트, 실제 Obsidian 설정 디렉터리를 찾는다. 기존 제외 규칙을 읽고 `git status --short`와 `git ls-files -- <path>`로 현재 상태를 확인한다.
2. 사용자가 백업하거나 공유하거나 기기 간 동기화할 범위에 맞춰 추적 기준을 정한다. 노트, 첨부 파일, 설정, 작업 공간 상태, 플러그인 데이터를 각각 판단한다. 설정에 경로, 자격 증명, 비공개 데이터가 들어 있는지 확인하고 실제 값은 노출하지 않은 채 결과를 보고한다.
3. 요청한 기준에 필요한 제외 규칙만 수정한다. 패턴의 시작 위치를 지정할 때는 해당 `.gitignore`가 있는 디렉터리를 기준으로 삼는다. 주석은 별도 줄에 둔다. 대표적인 포함 경로와 제외 경로를 `git check-ignore -v --no-index -- <path>`로 점검하고 `git ls-files -- <path>`로 추적 상태를 확인한다.
4. 제외 규칙에 해당하는 파일을 Git이 이미 추적한다면 따로 보고한다. 사용자가 추적 해제를 요청하면 영향받는 파일을 나열하고 인덱스와 작업본을 확인한 후 로컬 파일을 보존한다. 변경 후 스테이징된 diff와 작업본을 다시 확인한다.

Git의 [제외 패턴](https://git-scm.com/docs/gitignore)과 [규칙 진단](https://git-scm.com/docs/git-check-ignore) 문서를 참고한다.

## 내부 링크 점검

1. 요청 범위의 노트에서 링크를 읽는다. 링크 대상은 볼트에서 접근이 허용된 곳 전체에서 찾는다. 요청한 노트 폴더 밖의 노트와 첨부 파일도 포함한다. 위키링크, 임베드, Markdown 내부 링크를 확인한다. 외부 링크와 주석 또는 코드 안의 텍스트는 건너뛴다. Obsidian의 링크 확인 기능을 쓸 수 있으면 문맥에 따라 달라지는 대상을 확인한다.
2. 링크 문법에 따라 상대 경로는 출발 노트의 디렉터리에서, 볼트 루트 기준 경로는 볼트 루트에서 찾는다. 표시 이름과 프래그먼트는 파일 경로와 분리한다. 로컬 Markdown 링크는 프래그먼트를 먼저 분리한 후 경로와 프래그먼트의 퍼센트 인코딩을 각각 한 번 디코딩한다. `[[#Heading]]`처럼 프래그먼트만 있으면 출발 노트를 참조한다. 파일을 찾은 경우 확실하게 대조할 수 있는 제목이나 블록 참조를 점검한다.
3. 접근 제한이나 검사 범위 때문에 결론이 달라질 수 있으면 해당 결과를 미확인으로 표시한다. 필요한 범위를 검색한 뒤에도 일치하는 대상이 없으면 깨진 링크로 기록한다. 짧은 링크에 가능한 후보가 여럿이고 출발 노트의 위치나 Obsidian의 링크 확인 기능으로 대상을 특정할 수 없으면 후보를 모호한 링크로 보고한다. 실제로 누락을 확인한 제목과 블록은 따로 표시한다. 파일, 줄 번호, 링크 원문, 후보나 원인을 기록한다. 점검은 읽기 전용으로 진행한다.

지원되는 링크 형식은 Obsidian의 [내부 링크 가이드](https://help.obsidian.md/links)를 참고한다.
