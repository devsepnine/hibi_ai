# 비교 실험 설계

## 정답이 달라지는 사례 고르기

선택한 레코드를 내보내는 스킬이라면 기본 사례에서 체크한 두 행을 내보낸다. 조건은 한 번에 하나씩 바꾼다. 세 번째 행으로 키보드 포커스를 옮겨 명령 범위를 시험한다. 선택한 행 하나의 접근 권한을 없애 문서에 적힌 권한 처리 동작을 시험한다. 내보내기 기능의 검토를 요청해 리뷰 스킬과의 경계를 시험한다.

입력, 사용할 수 있는 자료와 허용 동작, 기대하는 담당 스킬, 관찰할 결과, 실패 판정 기준을 적는다. 결과 파일이나 선택된 레코드 ID를 확인할 수 있으면 그것으로 채점한다. 문구 자체가 계약에 포함될 때만 특정 표현의 일치를 검사한다.

## 공정한 비교 실행

모델, 프롬프트, 입력 자료, 도구 권한, 주변 지침을 같은 조건으로 맞춘다. 각 실행은 이전 답을 보지 않은 상태에서 시작하고 수정할 데이터는 별도 사본을 쓴다. 정답과 이전 결론은 제공하지 않는다. 대조군에서 대상 스킬의 진입점과 자동으로 읽히는 지침을 함께 제외한다. 분리가 불가능하면 무엇이 비교에 영향을 주는지 밝힌다. 책임이 겹치는지 판단할 때는 필요한 경우 이웃 스킬 하나 또는 둘을 함께 쓰는 조건도 비교한다.

두 결과물 모두 정확한 레코드를 내보냈다면 정확성은 동률로 기록한다. 추가 비용이 결정에 영향을 주면 측정한다. 양쪽이 모두 실패하면 스킬에 원인을 돌리기 전에 공통 입력과 채점 기준을 확인한다. 적은 표본으로도 해당 입력에서 생긴 실패나 이득은 보일 수 있다. 더 넓은 신뢰도를 주장하기 전에 사례 수와 실행 횟수를 밝힌다.

## 수정 위치 찾기

목록 감사에서는 이 스킬의 디렉터리에서 `python3 scripts/inventory.py /path/to/skills`를 실행한다. Python 표준 라이브러리만 사용한다. JSON에는 검사한 파일, 진입점이 없는 일반 디렉터리, 본문이 일치하는 파일 묶음이 나온다. 본문 일치 판정에서는 frontmatter와 문서 양끝의 공백, 원문과 짝을 이루는 한국어 미러를 제외한다. 종료 코드 1은 스킬 진입점이 없다는 뜻이다. 종료 코드 2이면 오류에 표시된 경로나 읽기 권한을 확인하고 목록을 다시 조사한 뒤 범위를 보고한다. 번역으로 동작이 달라지는지는 별도로 확인한다. 표현이 다른 지침, 문서의 일부분, 코드와 자산도 따로 비교한다.

- 실제 목록에 진입점이 없으면 패키징과 탐색을 확인한다. 목록에 있고 이름으로 불렀을 때 성공하지만 일반 요청에서 호출을 놓친 것이 관찰됐다면 선택 조건을 살핀다. 설명과 경쟁하는 지침을 확인한다.
- 호출된 스킬이 오래된 예시를 읽거나 필요한 자료를 찾지 못하면 참조 경로와 결과물까지 따라간다. 서비스를 쓸 수 없으면 그 서비스에 의존하는 동작은 미검증으로 남긴다. 오프라인 동작이 정의돼 있다면 별도로 시험한다.
- 두 스킬을 서로 바꿔 쓸 수 있어 보이면 같은 입력에서 요구하는 출력, 부수효과, 고유한 예외, 독립 설치 시 동작을 비교한다. 같은 문단이 필요한 곳마다 포함됐을 수 있다. 통합하려면 기존에 지원하던 각 경로를 누가 이어받는지 확인한다.

반복 감사에서는 처음 실패한 입력을 보관하고 수정 후 새 사례를 더한다. 무엇을 관찰해 고쳤는지와 어떤 검증이 남았는지를 독자가 구분할 만큼 실행 기록을 남긴다.
