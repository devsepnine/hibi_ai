# 스킬 분석과 개선

스킬 하나나 스킬 묶음을 검토할 때 사용한다. 사용자가 내리려는 결정, 검토할 소스나 설치본, 조사와 수정 중 어디까지 요청했는지 확인한다. 끝난 작업 하나에서 교훈을 찾는 회고는 설치된 경우 `skill-improvement`가 담당한다. 평가를 실행할 때는 기존 도구와 입력 자료를 활용한다.

## 각 스킬이 맡은 일 파악하기

1. 대상마다 실제 사용자가 할 요청, 필요한 입력, 스킬이 바꾸는 판단, 다른 사람이 확인할 결과물을 적는다. 진입점에서 관련 참조, 스크립트, 자산까지 따라간다. 이동이나 제거를 제안하기 전에 호출하는 곳, 자동으로 읽는 지침, 명시적 호출 경로를 찾는다.
2. 기본 모델 응답이나 프로젝트의 기존 규칙까지 포함해 가장 가까운 대안을 찾는다. 같은 요청을 양쪽에 대입해 어느 쪽이 무엇을 맡는지 비교한다. 표현이 달라도 같은 행동을 지시할 수 있다. 포커스 상태를 설계하는 사람과 구현된 상태를 검사하는 사람은 같은 용어를 쓰면서 서로 다른 결과물을 만든다.
3. 여러 스킬을 조사할 때는 전체 목록과 실제 행동을 시험한 대상을 표시한다. 필요하면 [목록 검사기](scripts/inventory.py)에 스킬들의 상위 디렉터리를 인자로 넘긴다. 바로 아래 스킬을 열거하고 진입점, 참조, 규칙에 본문이 일치하는 파일이 있는지 찾는다. 일치한 파일은 원문을 대조할 후보로 사용한다.

## 효용성, 발동 조건, 실행 결과 시험하기

- **효용성.** 답을 보기 전에 어떤 결과가 사용자에게 더 나은지 정한다. 대상 스킬을 제공한 경우와 제외한 경우에 같은 요청과 입력을 주고, 가장 가까운 대안은 양쪽에서 모두 쓸 수 있게 한다. 같은 기준으로 결과물을 읽어 개선, 동률, 회귀, 근거 부족을 기록한다. 실제 작업에 끼친 영향과 추가로 읽은 자료, 절차, 도구 호출, 유지 비용을 함께 판단한다. 사용 수요나 드문 실패가 초래할 결과를 확인할 수 있으면 그 근거도 쓴다.
- **발동 조건.** 일반적인 사용자 표현, 이웃 스킬이 맡아야 할 유사 요청, 필요한 경우 둘을 함께 써야 하는 요청을 시험한다. 기대하는 담당 스킬과 이유를 적는다. 목록 노출, 설명을 읽은 평가자의 선택, 런타임에서 관찰한 호출, 작업 성공을 각각 기록한다. 항상 읽히는 스킬은 무관한 작업에 끼치는 영향도 살핀다. 명시적으로 부르는 스킬은 이름으로 호출하는 경로를 시험한다.
- **실행 결과.** 대표 작업을 요청부터 결과물까지 따라간다. 자료나 도구가 없거나 사용자가 범위를 좁히는 등 조건 하나가 바뀌면 행동도 달라져야 하는 사례를 시험한다. 참조 자료와 현행 프로젝트 관례를 확인하고 실제 출력, 상태, 오류를 살핀다. 의존성 때문에 실행할 수 없으면 어떤 근거가 부족한지 적는다.

쓰기, 전송, 삭제 명령은 사용자 승인 범위와 예고한 부수효과를 대조한다. 행동 실험은 버려도 되는 사본에서 수행한다. 기본값이 추가 업무를 만드는지, 오래된 예시가 규칙과 충돌하는지, 선택 자료가 필수 조건으로 바뀌었는지 살핀다. 결과가 달라지는 경로와 상황을 근거로 제시한다.

사례 선택이나 모호한 결과 해석에는 [비교 실험 설계](references/comparative-trials-ko.md)를 참고한다. 독립 평가자에게 과제를 줄 때는 실행에 필요한 입력만 전달하고 기대 결과는 채점에 사용한다.

## 판단하고 수정한 뒤 재검증하기

잘못된 행동이나 결과물을 만들 수 있는 문제부터 보고한다. 중요한 발견마다 해당 파일이나 지침, 발동 조건, 관찰된 결과, 근거, 필요한 최소 변경을 제시한다. 동률인 사례에서는 추가 효용이 확인되지 않았다고 기록한다. 고유한 작업을 맡는 것이 검증된 스킬은 유지한다. 설명 범위 축소, 규칙 수정, 상세 지침 이동, 같은 책임의 통합, 다른 곳에서 해당 작업을 지원하는 지침의 정리를 검토한다. 통합을 제안하기 전에 각 스킬만의 예외, 호출부, 설치 방식을 확인한다.

검토 요청에는 발견 사항과 수정안을 반환한다. 수정까지 요청받았다면 담당 소스와 필요한 미러를 고친 뒤 원래 실패 사례, 처음 보는 변형 사례, 영향을 받지 않아야 할 인접 작업을 다시 시험한다. 설명이 바뀌면 패키지 탐색과 목록 예산도 확인한다. 새 관찰이 추가 수정을 뒷받침하는 동안 반복한다. 대상별 결정, 시험한 범위, 회귀 여부, 남은 의문을 남긴다. 비교 근거가 부족하면 판정 보류로 기록한다.
