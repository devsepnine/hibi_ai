# 기능맵

`docs/FEATURES.md` 를 만든다. 사용자나 팀원이 **말하는 방식** — "사이드바에
뭐가 잘 안돼요", "입금 문구가 잘 입력이 안돼요" — 을 받아서, 코드베이스를
먼저 뒤지지 않고도 AI가 그 기능을 구현한 파일에 바로 도달하게 하는 조회표다.

## 왜 이 구성인가

제보는 제품 용어로 들어온다. 화면 어디였는지, 라벨에 뭐라고 적혀 있었는지,
무엇을 하려던 참이었는지. 반면 코드는 모듈 단위로 나뉘어 있다. 이 간극에서
AI는 처음 열 번의 도구 호출을 날린다 — "sidebar"로 grep해서 마흔 개가 나오고,
엉뚱한 것부터 읽는다. 기능맵은 사람이 기능을 묘사하는 방식 그대로 색인을 만들어
이 간극을 메운다. **화면 위치, 사용자가 쓰는 단어, 화면에 보이는 실제 문구**.

코드맵(`doc-updater`, `docs/CODEMAPS/`)과 다른 점이 바로 이것이다. 코드맵은
"코드가 어떻게 구성되어 있나"에 답하고, 기능맵은 "이 제보는 어디에 떨어지나"에
답한다. 둘은 서로 링크하되 한쪽 내용을 다른 쪽에 복사하지 않는다.

읽는 쪽은 모호한 제보가 올 때마다 이 문서를 로드하는 AI다. 그러니 모든 줄이
토큰 값을 해야 한다. 산문이 아니라 경로와 문자열로 쓴다.

## 워크플로우

### 1. 사전 점검 — 신규 작성인가 갱신인가

```bash
test -f docs/FEATURES.md && grep -m1 -E '^(Verified at|검증 시점)' docs/FEATURES.md
git rev-parse --short HEAD
```

- **맵이 없음**: 전체 작성(2–6단계).
- **맵이 있음**: 갱신 모드. 기록된 SHA에서 diff를 뜬다:
  `git diff --name-status -M <sha>..HEAD`. diff에 파일이 걸린 항목은 의심
  대상이므로 다시 검증한다. 이름이 바뀐(`R`) 파일은 경로를 고쳐 잇고, 파일이 모두
  삭제된(`D`) 항목은 지우며, 새로 생긴 라우트·화면·UI 문구는 새 항목이 된다.
  건드리지 않은 항목은 다시 생성하지 않는다 — 맞는 항목을 다시 쓰면 리뷰 노이즈만
  는다. 보고에는 추가·변경·삭제된 항목을 나눠 적는다.
- **기록된 SHA에 도달할 수 없음**(rebase, shallow clone): 그 사실을 알리고 모든
  경로를 전부 재검증한다. 말없이 새로 만들어 덮어쓰지 않는다.

### 2. 기능은 바깥에서 안으로 찾는다

디렉터리 트리가 아니라 사용자가 보거나 호출할 수 있는 것에서 시작한다. 트리는
개발자가 일을 나눈 방식이고, 그건 정확히 사용자가 모르는 어휘다.

| 표면 | 주로 있는 곳 |
|---|---|
| 라우트 / 화면 | 라우터 설정, `app/`·`pages/` 디렉터리, 내비게이션 스택 |
| 상주 영역 (사이드바, 헤더, 탭바, 모달) | 레이아웃 컴포넌트, shell/frame 파일 |
| 메뉴와 내비 항목 | 내비 설정 배열, 메뉴 정의 |
| 보이는 문구 | i18n 리소스 파일(`locales/`, `*.json`, `*.arb`, `strings.xml`), JSX에 하드코딩된 텍스트 |
| 에러와 토스트 | 에러 메시지 상수, toast/notification 호출부 |
| CLI / API 제품 | 커맨드 정의, 플래그 파서, 라우트 핸들러, 에러 코드 |

기능 하나 = 사용자가 한 덩어리로 부르는 것("입금", "사이드바 즐겨찾기",
"로그인"). 두 부분이 따로 고장 나고 사용자도 다르게 부르면 나누고, 사용자가
둘을 구별하지 않으면 합친다.

### 3. 기능마다 데이터까지 따라 내려간다

기능마다 코드를 읽어 실제 호출 체인을 따라간다 — UI 컴포넌트 → 이벤트 핸들러 /
상태 스토어 → API 클라이언트 → 서버 핸들러 → 저장소. 각 단계의 파일을 기록한다.
체인이 공용 인프라(HTTP 클라이언트, ORM 베이스)로 들어가는 지점에서 멈추고,
그 공용 의존은 모든 기능에 나열하지 말고 "공유 의존"으로 적는다.

적는 경로는 전부 이번 실행에서 실제로 연 파일이어야 한다.

### 4. 어휘를 수집한다

맵이 작동하게 만드는 핵심 단계다. 기능마다 세 종류의 단어를 모으고 서로
섞지 않는다. 조회할 때 쓰임새가 다르기 때문이다.

- **실제 UI 문구** — 배포된 그대로의 라벨, 버튼, placeholder, 에러 문구와 i18n
  키. grep 앵커이므로 소스에서 글자 그대로 복사한다. 절대 바꿔 쓰지 않는다.
- **화면 위치** — 사용자가 손가락으로 가리킬 영역("좌측 사이드바", "입금 폼
  상단", "설정 → 알림").
- **사용자 별칭** — 사람들이 실제로 부르는 말. 구어 표현, 다른 언어(`입금` /
  `deposit`), 유의어(`충전`, `송금 메모`), 흔한 오타. 별칭은 추정이므로 그렇게
  표시한다. grep 대상이 아니라 매칭 대상이다.

별칭 하나가 여러 기능에 맞으면 전부에 남기고, 별칭 인덱스에 `(ambiguous)` 로
충돌을 표시한다. 조회 단계는 아무거나 하나 고르지 말고 묻거나 둘 다 확인해야 한다.

### 5. 함정은 근거가 있을 때만 적는다

함정은 해당 기능의 알려진 실패 지점이다. 한글 입력을 삼키는 IME 조합 처리,
마지막 키 입력을 버리는 debounce, 오래된 잔액을 보여주는 캐시 같은 것. 하나하나
가리킬 수 있는 근거가 필요하다 — 코드 주석, 코드 안의 방어 로직, 과거 수정 이력:

```bash
git log --oneline -i -E --grep='fix|bug|revert|hotfix|수정|버그' -- "<file>" ... | head -10
```

기능의 파일을 반드시 명시해서 넘긴다 — 목록이 비면 저장소 전체를 검색하게 되어
모든 수정이 관련 있어 보인다.

근거가 없으면 함정도 없다. 지어낸 함정은 문서의 권위를 등에 업고 다음 디버거를
엉뚱한 길로 보낸다.

### 6. 검증하고, 연결한다

보고 전에:

```bash
# 맵에 적힌 경로가 전부 존재하는지 (경로는 `/` 를 포함해야 하므로 `deposit.memo` 같은 i18n 키는 제외)
grep -ohE '`[^` ]*/[^` ]*\.[A-Za-z0-9]{1,5}`' docs/FEATURES.md docs/features/*.md 2>/dev/null \
  | tr -d '`' | sort -u | while read -r p; do test -e "$p" || echo "MISSING $p"; done
```

- 실제 UI 문구는 전부 소스에서 grep되어야 한다(`grep -rF "<문구>"`). 안 걸리면
  바꿔 쓴 것이거나 낡은 것이다 — 남겨두지 말고 고친다.
- 기능마다 테스트 경로가 최소 하나 있거나, `tests: none` 을 명시한다. 비어 있다는
  사실 자체가 정보다.
- 헤더에 `검증 시점 <sha> · <YYYY-MM-DD>` (영문 템플릿은 `Verified at`)을 기록한다
  — 갱신 모드가 이 값을 다시 읽는다.

그다음 제보가 들어왔을 때 AI가 맵을 찾게 만든다. 프로젝트 `CLAUDE.md` /
`AGENTS.md` 의 디버깅 관련 섹션에 한 줄 포인터를 제안하고, 사용자가 동의하면
추가한다:

```markdown
- 모호한 버그 제보("사이드바의 X가 안 돼요")? 코드를 검색하기 전에 `docs/FEATURES.md` 에서 먼저 찾는다.
```

맵 작성은 콘텐츠 변경이므로 `CLAUDE.md` 의 작업 후 리뷰 게이트가 적용된다.

## 문서 템플릿

`assets/feature-map-template-ko.md` 를 쓴다. 섹션 순서를 지킨다. 조회 절차가
맨 앞(AI가 가장 먼저 읽는다), 그다음 두 인덱스, 그다음 항목.

**크기**: 기능이 ~30개 또는 ~400줄을 넘으면 `docs/FEATURES.md` 에는 조회 절차와
두 인덱스만 남기고 항목은 `docs/features/<feature-id>.md` 로 옮긴다. 인덱스는
조회 때 통째로 훑기 때문에 한 파일에 두고, 항목은 하나씩 열기 때문에 나눈다.

## 작성 규칙

- **ID는 안정적인 kebab-case** (`deposit-memo`) — UI 라벨이 바뀌어도 인덱스와 다른
  문서가 같은 ID로 참조할 수 있게.
- **설명 말고 경로** — "메모 입력 컴포넌트"보다 `src/features/deposit/MemoInput.tsx`.
- **코드 경로는 단계당 한 줄** — 단순 전달만 하는 단계는 건너뛴다.
- **줄 번호 금지** — 수정할 때마다 흔들리고 아무도 다시 확인하지 않는다. 큰
  파일이면 대신 심볼 이름을 적는다(`MemoInput.tsx` → `handleCompositionEnd`).
- **모르는 건 모른다고** — `tests: none`, `pitfalls: none` 은 정직하다. 추측한 값은 아니다.
