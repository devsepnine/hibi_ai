# UI 스타일 설계

시스템 이름과 버전, 화면 캡처, 기존 제품 중에서 시각 기준을 정한다. 요청이 ‘레트로’나 ‘모던’ 정도라면 제품의 용도와 사용자에 어울리는 방향을 선택하고 근거를 밝힌 뒤 작업한다. 사용자가 비교를 원하거나 선택에 따라 결과물이 크게 달라지면 대안을 보여 준다.

- 특정 시대를 재현할 때는 [시대별 스타일](references/historical-styles-ko.md)에서 계열을 고른다. 그 계열의 창 구조, 컨트롤 상태, 명령 실행 방식을 한 작업 흐름 전체에 적용한다. 예시에 없는 플랫폼을 지목했다면 [플랫폼 색인](references/platform-index-ko.md)을 참고한다.
- 현대적인 제품은 [모던 스타일](references/modern-styles-ko.md)을 참고해 대상 시스템과 사용할 컴포넌트를 정한다. 기존 제품을 개편할 때는 사용자가 알아보는 단서와 바꾸려는 부분을 먼저 짚는다.
- 스타일 가이드, 구현 명세, 비교안에는 [설계 예시](references/style-specimen-ko.md)를 활용한다. 로컬에서 열 수 있는 [인터랙티브 예제](assets/style-specimen.html)는 같은 대기열을 여러 스타일로 보여 준다. 예제의 수치는 설명을 위해 선택한 값이다.

결과는 요청한 화면, 코드, 가이드에 직접 반영한다. 실제에 가까운 콘텐츠로 작업을 수행하면서 활성 상태와 동시에 나타날 수 있는 다른 상태를 확인한다. 중요한 단서마다 시대 원문에서 가져온 것, 현 제품의 관례, 의도적으로 바꾼 것을 구분해 설명한다. 역사적 충실도가 중요한 작업에서 픽셀 단위의 정확성을 주장하려면 기준으로 삼은 판본이나 화면을 특정한다.
