# UI style direction

Use a named system, release, screenshot, or existing product as the visual anchor. If a brief says only “retro” or “modern”, infer a direction from the product and its users where possible. State the choice and proceed. Offer alternatives when the user asks to compare or when the choice changes the deliverable.

- For a period recreation, choose a family from [historical styles](references/historical-styles.md). Carry its window structure, control states, and command model through one complete task. For a named platform outside those examples, consult the [platform index](references/platform-index.md).
- For a contemporary product, select the target system and its available components using [modern styles](references/modern-styles.md). For a redesign, identify what existing users recognize and what should change.
- For a style guide, implementable specification, or comparison, use the [worked example](references/style-specimen.md). A local [interactive specimen](assets/style-specimen.html) presents the same queue in several visual languages. Its values are illustrative.

Deliver the requested screen, code, or guide. Test the chosen cues on an actual task with realistic content, an active state, and a competing state. Record whether each important cue comes from the period source, the target product, or a deliberate adaptation. If the brief asks for historical fidelity, identify the exact edition or screenshot behind any claim of pixel accuracy.
