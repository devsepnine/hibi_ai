# 시대별 스타일

요청한 시기에 맞는 판본을 선택한다. 아래 대기열 사례는 원문에서 읽은 원칙으로 새로 구성했다. 연도는 참고한 판본의 발행 시점이다.

## 데스크톱 창과 도구

**클래식 Macintosh.** 창 외곽선, 활성 창임을 알아볼 수 있는 제목 영역, 절제된 구분선, 기본 명령 표시를 사용한다. 가로 줄무늬가 있는 활성 제목 막대와 경계가 뚜렷한 목록은 흑백에서도 문서 창의 성격을 드러낸다. 대기열에서는 선택 여부를 체크 표시로, 키보드 포커스를 별도 외곽선으로 구분한다. 웹으로 옮길 때는 입력 요소의 접근 가능한 이름과 글자 확대를 살린다. 출처는 1992년 *Macintosh Human Interface Guidelines*의 “Windows”와 “Controls”다.

**Motif와 CDE.** 돌출된 명령 버튼과 안으로 들어간 작업 영역에는 같은 방향에서 빛이 비친 것처럼 테두리를 그린다. 버튼을 누르는 동안 밝고 어두운 테두리의 방향을 뒤집는다. 눌림, 계속 켜진 토글, 현재 키보드 위치는 유지되는 시간이 다르므로 표시도 구별한다. 한 가지 결정을 내릴 때는 대화상자를 쓰고 작업을 이어가야 할 때는 관련 도구를 계속 쓸 수 있게 한다. 출처는 1993년 *OSF/Motif Style Guide*와 2002년 *Common Desktop Environment Style Guide and Certification Checklist*다.

**Windows 95.** 자주 쓰는 명령은 도구 모음에서 바로 실행하고 메뉴에서도 이름으로 찾을 수 있게 한다. 선택한 대상의 관련 설정은 속성 페이지에 모은다. 편집값을 모아서 적용하는 경우 적용 버튼이 반영할 값, 취소로 버릴 수 있는 값, 설정이 속한 문서를 정한다. Windows용으로 다시 만들 때는 액세스 키와 포커스 관례를 지킨다. 출처는 1995년 *The Windows Interface Guidelines for Software Design*의 “Menus, Controls, and Toolbars”와 속성 시트 지침이다.

**OpenStep.** 문서 편집기의 속성 패널은 현재 선택을 따라간다. 패널 제목과 속성으로 편집 대상을 드러내고 다른 객체를 선택하면 패널 값도 예측 가능하게 바뀌게 한다. 명령이 적용되는 문서와 키보드 입력을 받는 창을 구별한다. 출처는 1996년 *OpenStep User Interface Guidelines*의 “Inspector Panels”와 키 창 및 주 창 설명이다.

## 재질과 글자로 드러내는 스타일

**Aqua.** 기본 명령의 강조색과 입체적인 표면을 실제 주요 행동에 사용한다. 문서에 관한 결정은 해당 창에 붙은 시트로 보여 주고 다른 문서에서는 계속 작업할 수 있게 한다. 웹으로 옮길 때는 둥글고 윤기 나는 표면과 함께 시트의 대상과 포커스 동작도 옮긴다. 시안에서 선택한 그라데이션 색상 위치는 제작자가 정한 값이다. 출처는 2001년 *Aqua Human Interface Guidelines*의 “Sheets”와 “Push Buttons”다.

**Windows Phone의 Metro.** 큰 글자와 정렬선, 여백으로 정보의 순서를 만든다. 파노라마는 이웃한 섹션이 이어짐을 보여 주고 피벗은 서로 관련된 보기 사이를 이동한다. 콘텐츠가 이 관계를 가질 때 해당 방식을 선택한다. 교통 안내판이라면 목적지와 다음 출발 시간을 강조하고 노선명은 보조 제목으로 둔다. 다른 섹션으로 가는 조작은 쉽게 찾을 수 있어야 한다. 번역 문구를 큰 글자로 표시해도 내용을 읽을 수 있게 한다. 출처는 2010년 *UI Design and Interaction Guide for Windows Phone 7*의 “Metro”, “Panorama”, “Pivot”이다.

**2018년 Material Design.** 표면과 높이, 전환 동작으로 항목의 이동 경로를 드러낸다. 밀도는 작업에 맞춘다. Rally는 압축된 행과 글자로 금융 데이터를 비교하게 하고 Crane은 여행지를 보여 주는 데 더 넓은 공간을 쓴다. 제품의 주된 작업에 맞는 사례에서 정보 위계를 가져온다. 출처는 *Material Design*의 “Applying density”, “Choreography”, Rally와 Crane 사례다.

## 아이콘과 소프트 키, 카드

**Windows XP 아이콘.** 실제 도구 모음 크기에서도 사물의 윤곽을 알아볼 수 있게 한다. 객체 아이콘은 해당 판본의 색채와 투시 방향을 참고한다. 작은 크기에서는 내부 묘사를 줄이고 원래 표시 크기로 결과를 비교한다. 복원이라면 각 크기에 해당하는 원본 자산을 확인한다. 출처는 2001년 *Windows XP Visual Guidelines*의 “Icons”다.

**키패드가 있는 Series 60.** 피처폰 목록에는 현재 행, 현재 보기, 물리 소프트 키에 대응하는 위치의 명령 문구가 필요하다. 옵션 메뉴를 열면 키의 역할도 바뀐다. 메뉴를 열기 전과 후를 모두 보여 준다. 단말기 외곽만 그리면 이 조작 관계를 알 수 없다. 출처는 2003년 *Series 60 UI Style Guide*의 “Keys”와 화면 영역 설명이다.

**초기 iPhone과 webOS.** 2008년 iPhone 사진 탐색기라면 탐색 막대로 어느 모음에 있는지 보여 주고 도구 모음에서 사진에 명령을 실행하게 한다. 슬라이드 쇼에서는 사용자가 조작부를 부를 때까지 사진이 화면 전체를 쓸 수 있다. 2011년 TouchPad 작업 화면에서는 여러 활동을 카드로 유지하고 관련 활동을 한 묶음으로 보여 줄 수 있다. 비교안에는 각 시스템에서 열어 둔 작업으로 돌아오는 방법을 담는다. 출처는 2008년 *iPhone Human Interface Guidelines*와 2011년 *HP Touchpad webOS Design Guidelines*다.

## 재현의 정도

박물관용 복원은 지정한 버전의 컨트롤 위치와 메뉴 동작이 중요할 수 있다. 같은 상태의 원본 화면과 비교하고 불확실한 부분을 기록한다. 시대 분위기를 살린 실사용 앱은 윤곽과 정보 위계, 상태 표시를 유지하면서 터치 영역, 글자 확대, 키보드 조작, 동작 줄이기를 대상 환경에 맞출 수 있다. 현대화 작업에서는 익숙한 명령과 이름, 선택 범위를 유지하면서 시각 표현을 바꿀 수 있다. 어느 경우든 개편 전후에 실제 작업 하나를 수행해 비교한다.
