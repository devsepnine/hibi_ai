# 작업 하나로 시각 스타일 명세하기

로컬에서 [대기열 예제](../assets/style-specimen.html)를 연다. 스타일을 선택하고 주문을 체크한 뒤 키보드 포커스를 다른 컨트롤로 옮겨 선택한 주문을 처리한다. 같은 조작을 각 스타일에서 비교한다. Fluent 예시는 중립적인 행과 강조 명령을 쓰고, Material 예시는 색조가 있는 표면과 그 위의 전경색을 짝짓는다. Apple 예시는 하단 명령 막대를 별도 영역으로 띄운다. 세 가지 모두 웹을 위해 직접 정한 값으로 구성했으며 오프라인에서 실행할 수 있다.

제품 스타일 가이드에는 실제 컴포넌트와 지원하는 입력 방식을 쓴다. 아래는 다른 사람이 구현할 수 있도록 배차 대기열을 명세하는 예다.

1. **정보 위계와 밀도.** 운영자는 상태로 지연 건을 찾고 주문번호를 확인한 뒤 함께 처리할 대상을 고른다. 비교할 값은 같은 열에 배치한다. 상태 문구가 길어지면 줄을 바꿔 주문번호와 명령을 계속 볼 수 있게 한다.
2. **역할과 값.** 바탕, 작업 영역, 본문, 선택된 행, 키보드 포커스, 경고를 현재 테마에 대응시킨다. 바뀌는 역할마다 예시 값이나 기존 토큰을 제시한다. 흑백 스타일에서는 체크 표시로 선택을 나타내고 별도의 외곽선이 포커스를 따라갈 수 있다. 테마를 지원하는 작업 화면에서는 선택 배경이 달라져도 상태 문구가 보여야 한다.
3. **컴포넌트 상태.** 포커스가 다른 곳에 있는 선택 행과 선택되지 않은 포커스 행을 각각 보여 준다. 명령에는 선택 개수를 표시한다. 처리 후 다음 조작 위치가 분명해야 한다. 처리 실패가 가능할 때는 제품이 제공하는 복구 방법을 쓴다.
4. **레이아웃과 언어.** 열을 유지할지 세로로 쌓을지는 콘텐츠의 폭으로 정한다. 오른쪽에서 왼쪽으로 읽는 언어를 지원하면 방향성이 있는 탐색 요소를 반전한다. `ORD-0217` 같은 식별자는 글자와 숫자의 순서를 보존하도록 분리한다. 실제 식별자 옆에 번역된 레이블을 놓아 확인한다.
5. **모션과 근거.** 움직임으로 바뀐 대상과 목적지를 연결한다면 동작 줄이기 상태에서도 변화를 이해할 수 있는 최종 모습을 정한다. 같은 상태의 대표 화면을 넓은 폭과 좁은 폭에서 비교한다. 설계 제안과 렌더링으로 관찰한 결과를 구분한다.

작은 스타일 수정에는 영향을 받는 항목만 적용한다. 과거의 픽셀 치수나 예시 색상, 플랫폼 토큰 이름을 공식 값으로 설명하려면 해당 값을 명시한 출처를 확인한다.
