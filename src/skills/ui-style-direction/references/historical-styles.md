# Historical styles

Use the edition that matches the brief. The queue examples below are original adaptations. A date identifies a source edition, not the lifetime of a style.

## Compact desktop windows

**Classic Macintosh.** Use a strong window outline, an identifiable active title region, restrained separators and a marked default command. An active title bar with horizontal stripes and a clearly bounded list will read as a classic document window even in monochrome. In a queue, let a check mark show membership and a separate outline follow keyboard focus. For a modern web adaptation, keep the native input name and scalable text. The source is *Macintosh Human Interface Guidelines*, 1992, “Windows” and “Controls”.

**Motif and CDE.** Give the raised command and recessed work area a consistent light direction. Invert the edge treatment while a button is pressed. A pressed button, a latched toggle, and the keyboard location have different lifetimes and need distinguishable states. Use a dialog for a bounded decision and keep related tools available when work must continue. Sources include *OSF/Motif Style Guide*, 1993, and *Common Desktop Environment Style Guide and Certification Checklist*, 2002.

**Windows 95.** Organize frequent actions in a toolbar and retain their named menu commands. Use property pages for related settings on an object. When an editor stages a change, specify what Apply commits, what Cancel can still discard, and which document owns it. Maintain the platform's access key and focus conventions when rebuilding on Windows. The source is *The Windows Interface Guidelines for Software Design*, 1995, “Menus, Controls, and Toolbars” and the property sheet guidance.

**OpenStep.** In a document editor, an inspector follows the selection. Use the panel title and relevant properties to identify what is being inspected. Switching to a new object should update the panel predictably. Distinguish the document being operated on from the window receiving keyboard input. The source is *OpenStep User Interface Guidelines*, 1996, “Inspector Panels” and its discussion of key and main windows.

## Materials and typography as identity

**Aqua.** Tie the default command's accent and shaped surface to a genuine primary action. Attach a document decision to its owning window as a sheet and keep other documents usable. On the web, translate the ownership and focus behavior as well as the rounded, highlighted surface. Any gradient stops in a mockup are author choices. The source is *Aqua Human Interface Guidelines*, 2001, “Sheets” and “Push Buttons”.

**Metro on Windows Phone.** Build hierarchy with prominent type, strong alignment and open space. A panorama suggests neighboring sections, while a pivot moves between related views. Choose one when the content has that relationship. In a transit board, emphasize the destination and next departure, let a quieter heading identify the line, and expose other sections through a reachable control. Preserve all localized labels at large text sizes. The source is *UI Design and Interaction Guide for Windows Phone 7*, 2010, “Metro”, “Panorama”, and “Pivot”.

**Material Design of 2018.** Use surface, elevation and transition to show where an item went. Choose density for the task. Rally organizes financial comparisons with compact rows and typography. Crane gives travel destinations more visual space. Reuse the underlying hierarchy when the product matches one of those tasks. The sources are *Material Design*, “Applying density”, “Choreography”, and the Rally and Crane studies.

## Icons, soft keys and cards

**Windows XP iconography.** Keep the object's silhouette readable at the actual toolbar size. Use the edition's colored artwork and perspective as the reference for object icons. Simplify internal details for small sizes and compare the result at native scale. For a restoration, inspect the asset for each size that exists. The source is *Windows XP Visual Guidelines*, 2001, “Icons”.

**Series 60 on a keypad.** A list on a feature phone needs a visible current row, an indication of the current view, and command labels positioned over the corresponding soft keys. Opening an options menu changes what those keys do. Show the before and after states. An illustrated handset frame alone conveys none of those relationships. The source is *Series 60 UI Style Guide*, 2003, “Keys” and its description of panes.

**Early iPhone and webOS.** For a 2008 iPhone photo browser, a navigation bar locates the collection and a toolbar acts on the photo. During a slideshow the image can take the screen until the person requests controls. For a 2011 TouchPad workspace, separate activities can remain visible as cards, with related activities stacked. In a comparison, show how the person returns to an open task in each system. Sources are *iPhone Human Interface Guidelines*, 2008, and *HP Touchpad webOS Design Guidelines*, 2011.

## Choose the degree of fidelity

A museum reconstruction may require exact control placement and original menu behavior. Compare it with the specified release in the same state and document uncertain details. A production app with a period appearance can keep the silhouette, hierarchy and state cues while adapting hit regions, text scaling, keyboard operation and reduced motion to its host. A migration can preserve familiar commands, names and selection scope while replacing their visual treatment. In each case, compare a real task before and after the change.
