# 모던 디자인 시스템과 현대화

대상 플랫폼, 설치된 컴포넌트 라이브러리, 지원 테마와 기존 화면을 먼저 본다. 별도 요청이 없으면 제품의 시각 정체성을 유지한다. 아카이브의 Material과 Aqua 문서는 과거 판본이다. 특정 버전의 동작을 설명할 때는 현재 공식 문서와 제품에서 쓸 수 있는 버전을 확인한다.

## 화면에 맞는 시스템 선택

- **생산성 도구의 Fluent 2.** 중립 표면과 제품에 있는 텍스트, 브랜드, 상태, 상호작용 토큰에서 시작한다. 라이브러리의 한 행에는 중립 배경, 선택 표시, 독립적인 포커스 테두리, 상태 문구를 함께 쓸 수 있다. 열린 명령 메뉴처럼 위에 떠 있어야 하는 요소에 높이를 준다. 두 테마에서 메뉴 경계와 포커스를 확인한다. [Fluent 디자인 토큰](https://fluent2.microsoft.design/design-tokens) · [Fluent 높이](https://fluent2.microsoft.design/elevation)
- **Material 제품의 Material 3.** 컴포넌트를 선택한 뒤 배경과 그 위 콘텐츠의 색상 역할을 짝짓는다. 주요 강조 컨테이너 위의 글자에는 그 컨테이너용 전경색을 쓴다. 팔레트나 테마를 바꿀 때도 이 짝을 유지한다. 선택, 키보드 포커스, 오류가 겹칠 수 있는 컴포넌트는 실제 배경 위에서 그 조합을 보여 준다. [Material 3 색상 역할](https://m3.material.io/styles/color/the-color-system/)
- **현재 Apple 플랫폼.** 지원되는 시스템 탐색 요소와 컨트롤을 사용한다. Liquid Glass를 지원하는 환경에서는 탐색 요소와 컨트롤이 콘텐츠 위의 층을 이룬다. 밝은 사진과 어두운 콘텐츠 위에서 읽기 영역의 가독성을 확인한다. 시스템의 투명도 줄이기 설정과 제품이 지원하는 이전 환경의 표현을 확인한다. [Apple 재질 가이드](https://developer.apple.com/design/human-interface-guidelines/materials)
- **웹 제품의 자체 스타일.** 사용자가 그 제품을 알아보는 특징에서 시작한다. 사진 카탈로그는 큰 사진과 조용한 조작부가 어울리고, 배차 콘솔에서는 정렬된 값과 촘촘한 행, 계속 보이는 작업 범위가 중요하다. 모서리나 그림자를 정하기 전에 어떤 콘텐츠가 공간을 차지해야 하는지 명세한다. 2018년 Material의 Rally와 Crane이 이 차이를 보여 준다.

## 익숙한 화면 개편

여러 청구서를 선택해 내보내는 일처럼 기존 사용자가 이미 알고 있는 작업 하나를 고른다. 명령 이름, 선택 상태를 알아보는 방법, 내보내기 후에도 선택된 대상을 기록한다. 새 컴포넌트에서도 그 의미를 이어 간다. 도구 모음을 선택한 항목에만 나타나는 명령 막대로 바꾼다면 포커스가 막대로 이동해도 선택 개수와 대상이 보여야 한다.

같은 데이터로 개편 전후의 작업을 따라간다. 해당하는 경우 서로 다른 상태의 항목을 함께 선택하고 긴 레이블과 기존 단축키 경로를 시험한다. 처리 결과와 돌아온 위치를 비교한다. 의도적으로 흐름을 바꿨다면 결과물에 달라진 경로를 보여 준다.
