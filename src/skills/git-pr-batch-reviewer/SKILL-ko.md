# 여러 PR 검토하기

사용자가 여러 PR이나 리뷰 대기열을 검토해 달라고 할 때 이 스킬을 사용한다. 대기열 목록을 요청하면 조건에 맞는 PR과 리뷰 상태를 전달한다. 각 PR의 검토에는 기존 `pull-request` 스킬을 사용한다.

## 검토 대상과 커밋 확인하기

1. PR별로 저장소와 번호를 확인한다. 사용자가 준 URL, 번호, 필터를 사용한다. 대기열을 볼 때는 조건에 맞는 PR 링크와 사용자가 요청한 리뷰 정보를 보여준다. 근거가 있으면 리뷰 요청, 이전 리뷰 이후 추가된 커밋, 미해결 스레드를 구분한다. 검토 범위가 불명확할 때만 대상 선택을 확인한다.
   대기열 전체나 필터에 맞는 PR 전체가 대상이면 추가 결과가 없을 때까지 페이지를 조회한다. `gh pr list`는 기본값으로 전체 결과를 30건까지만 가져온다. 저장소와 PR 번호로 중복을 제거한다. 권한이나 API 한도로 확인할 수 없었던 범위를 알린다.
2. 선택한 PR의 URL, 상태, draft 여부, base ref와 커밋, head 커밋을 기록한다. 사용 가능한 GitHub 연동 도구나 `gh`로 확인한다. 예를 들어 `repository`에 대상 GitHub 저장소를, `pr_number`에 선택한 PR 번호를 넣고 다음 명령을 사용한다.

   ```bash
   gh pr view "$pr_number" --repo "$repository" \
     --json url,number,state,isDraft,baseRefName,baseRefOid,headRefOid
   ```

## 기록한 커밋 기준으로 PR별 검토하기

1. `pull-request` 스킬이 있으면 해당 리뷰 기준을 적용한다. PR 의도, diff, 관련 리뷰 논의, 검사 결과를 읽는다. 기록한 커밋의 diff를 검토한다. 현재 PR의 diff를 조회하는 경우 조회 전후 커밋을 대조하고 바뀌었다면 diff를 다시 받는다.
2. 추가 파일이 필요하면 검토한 커밋에서 읽는다. 신뢰할 수 있는 리비전은 필요에 따라 별도 체크아웃을 사용하고 그 커밋을 확인한다. 사용자의 현재 체크아웃을 보존한다. 신뢰할 수 없는 리비전은 커밋에서 파일을 직접 읽고 해당 리비전의 CI 결과를 확인할 수 있으면 활용한다. 자격 증명, 비공개 파일, 사용자가 공유하는 Git 데이터에 접근할 수 없는 일회용 샌드박스에서만 해당 리비전을 체크아웃하고 실행한다. 그 환경이 없으면 실행하지 못한 검사를 보고한다.
3. 발견 사항을 해당 PR과 커밋에 연결한다. 파일과 줄 또는 그에 준하는 근거, 영향, 검증 범위를 적는다. 같은 발견 사항을 반복하기 전에 기존 코멘트를 확인한다. 접근할 수 없거나 근거가 부족하면 누락된 내용을 알리고 다른 선택 PR의 검토를 계속한다.
4. PR별 결과를 요약한다. PR 링크, head 커밋, 발견 사항이나 리뷰 결과, 검증하지 못한 부분이나 막힌 이유를 적는다.

## 요청받은 리뷰 게시하기

1. 초안을 보여주고 사용자가 명시적으로 요청한 PR, 리뷰 동작, 코멘트만 게시한다. 승인과 변경 요청은 별개의 동작으로 다룬다.
2. 각 리뷰를 게시하기 직전에 PR 상태, draft 여부, base ref와 커밋, head 커밋을 다시 확인한다. 어느 하나라도 바뀌었거나 커밋을 확인할 수 없으면 해당 초안을 보류한다. 게시 전에 영향받은 리뷰를 갱신한다. 게시 도구에서 `commit_id`나 같은 역할의 필드를 지원하면 리뷰를 기록한 head에 연결한다. 인라인 지적의 경로, 줄, 변경 전후 위치를 GitHub PR diff에서 확인한다. 검토한 커밋에 연결할 수 없는 승인, 변경 요청, 인라인 발견 사항은 초안으로 유지한다.
3. PR별 리뷰 링크나 확인된 상태를 기록한다. 게시 결과가 불확실하면 재시도 전에 새 리뷰가 제출됐는지 조회한다. 끝내 확인할 수 없으면 그 사실을 알린다.
