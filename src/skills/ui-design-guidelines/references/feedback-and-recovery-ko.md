# 피드백과 복구

## 행동의 결과에 맞춰 확인 요청하기

쉽게 되돌릴 수 있는 변경은 그 자리에서 결과를 보여 준다. 제품이 이전 상태를 복원할 수 있을 때 실행 취소를 제공한다. 되돌릴 수 없는 큰 손실이 생기는 명령은 실행 전에 대상과 결과를 알린다. 확인 버튼에 실행할 동작의 이름을 쓰고 안전하게 빠져나갈 방법을 제공한다.

예를 들어 메일함에서 메시지를 복원할 수 있으면 보관 직후 실행 취소를 제공할 수 있다. 공유 폴더를 영구 삭제할 때는 폴더 이름과 누가 접근 권한을 잃는지 알려 준다. 취소했을 때의 상태와 처리에 실패했을 때 사용자가 보는 결과도 확인한다.

2018년 *Material Design*의 “Confirmation & acknowledgement”와 *GNOME Human Interface Guidelines*의 “Alerts”에서 사례를 볼 수 있다.

## 결과에 대해 확인된 정보 보여 주기

- **처리 중.** 전체 파일 수와 전송을 마친 파일 수처럼 의미 있는 단위를 알 수 있을 때 진행률을 보여 준다. 전체 작업량을 알 수 없고 대기가 체감될 때는 진행 중인 작업 이름과 완료율을 표시하지 않는 진행 표시기를 쓴다.
- **콘텐츠 없음.** 비어 있는 라이브러리에는 제품이 지원하는 첫 항목 추가 방법을 제시할 수 있다. 검색 결과가 비면 검색어를 바로 고칠 수 있게 한다. 불러오기에 실패하면 작업 맥락을 유지하고 복구할 방법이 있을 때 안내한다.
- **입력 오류.** 문제가 생긴 필드 곁에 원인과 구체적인 수정 방법을 표시한다. 사용자가 오류를 고치는 동안 유효한 입력값은 유지한다.
- **응답 끊김.** 서버에서 이미 변경을 적용했을 수 있다면 가능한 경우 초안을 보존하고 처리 결과를 확인하지 못했다고 알린다. 제품에 상태나 이력을 조회하는 화면이 있으면 거기서 결과를 확인할 수 있게 한다. 같은 명령을 다시 실행해도 안전할 때 재시도를 제공한다.

*GNOME Human Interface Guidelines*의 “Progress Bars”, 2018년 *Material Design*의 “Empty states”, 2010년 *User Experience Interaction Guidelines for Windows 7 and Windows Vista*의 “Error Messages”에서 사례를 볼 수 있다.
