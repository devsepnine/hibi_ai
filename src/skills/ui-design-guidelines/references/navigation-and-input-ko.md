# 탐색과 입력

## 목록과 항목 사이의 이동

여러 항목을 비교하는 작업에서는 목록과 선택한 항목의 상세 정보를 둘 다 읽을 수 있는 폭이면 나란히 보여 준다. 하나만 들어가면 상세 정보를 별도 화면으로 열고 목록으로 돌아가는 경로를 제공한다. 화면이 전환되는 폭은 확대된 글자를 포함해 실제 콘텐츠로 정한다. 폭이 바뀌어도 선택한 항목은 유지한다.

예를 들어 필터를 적용한 받은편지함 중간에서 메시지를 연다. 목록으로 돌아오면 같은 검색 조건과 스크롤 위치가 보여야 한다. 메시지가 삭제됐다면 가까운 행을 선택하거나 필터 결과가 비었다는 상태를 보여 준다. 키보드 사용자는 어느 경우에도 포커스를 이어받아 다음 작업을 할 수 있어야 한다.

2021년 *KDE Human Interface Guidelines*의 “Master Detail”과 2018년 *Material Design*의 “Component behavior”에서 화면 구성 사례를 볼 수 있다.

## 지원하는 입력 방식으로 기능에 접근하기

- **터치.** 자주 쓰는 행 단위 동작은 스와이프로 단축할 수 있다. 행 메뉴에 이름이 붙은 명령을 두는 등 화면에서도 해당 기능을 찾을 수 있게 한다. 인접한 기능 사이의 터치 영역은 대상 플랫폼의 관례에 맞춰 확인한다.
- **키보드.** 대화상자를 열고 닫는 과정까지 실제 작업 순서대로 포커스를 따라간다. 항목을 드래그해 순서를 바꾸는 기능이 있다면 선택한 항목을 위아래로 이동하는 명령처럼 같은 결과를 내는 방법을 제공한다.
- **방향키 리모컨.** 대상 리모컨에 어떤 버튼이 있는지 먼저 확인한다. 방향키와 선택, 뒤로 버튼이 있으면 방향키로 포커스를 옮기고 선택 버튼으로 항목을 열며 뒤로 버튼으로 해당 항목에 돌아온다. 행 경계를 넘을 때도 포커스가 보이고 이동 경로를 따라갈 수 있는지 확인한다. 편성표를 탐색하는 동안에는 포커스를 옮겨도 현재 채널의 재생과 시청 중 표시가 유지되어야 한다.

입력 방식별 사례는 2014년 *iOS Human Interface Guidelines*의 “Users Know the Standard Gestures”, *GNOME Human Interface Guidelines*의 “Keyboard Interaction”, 2022년 *Samsung Smart TV Design Guides*의 “Input Methods”를 참고했다. 제품이 지원하는 기기에 해당하는 항목을 적용한다.
