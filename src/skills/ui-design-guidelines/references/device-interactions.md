# Interaction decisions by device

## Handheld and pen input

Place frequently used phone actions within reach and keep their targets distinct when the keyboard opens. For short, repeated entries, offer a recent value or picker if the data supports it. When both a keypad and touch are available, keep the soft key label next to the physical action it describes. Sources include *Palm OS User Interface Guidelines*, 2003, Nokia's *Series 40 Touch and Type UI Style Guide*, 2010, and *One UI Design Guidelines*, 2018.

For recognized handwriting or scanned text, show the interpreted value before using it for a consequential action. Keep a route to correct that value and preserve the rest of the entry. A pen gesture can accelerate a command that is also discoverable through a control. Sources include *Newton 2.0 User Interface Guidelines*, 1996, and *PenPoint UI Design Guidelines*, 1991.

## Shared surfaces and spatial input

- At a tabletop, rotate or place labels for the people who need to read them. Define which person can manipulate an object while another operates elsewhere. Test two people acting on separate objects and reaching for the same object. The source is *Microsoft Surface 2.0 Design and Interaction Guide*, 2011, “Orientation & Layout”.
- For camera-based gesture control, distinguish presence, engagement, targeting and command activation. Show who is engaged and what remains selected if tracking is lost. Include a way to rest or disengage. The source is *Kinect Human Interface Guidelines*, 2.0, “Engagement”.
- In a headset, show a visible target cue and a distinct activation cue. For scene changes, keep a stable reference where possible and let the person initiate movement. Check the experience on the intended device before claiming comfort. The sources are *Designing for Google Cardboard*, 2016, “Feedback” and “Physiological considerations”.
