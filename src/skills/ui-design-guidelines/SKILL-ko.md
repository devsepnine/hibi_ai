# UI 디자인 가이드

사용자가 화면에서 하려는 일, 함께 봐야 하는 정보, 화면을 조작하는 방법부터 파악한다. 제품에 있는 컴포넌트와 시각 스타일을 활용한다. 선택한 설계를 사용자가 요청한 와이어프레임, 구현물, 가이드에 직접 반영한다.

화면 이동을 바꾸면서 제품 스타일을 유지해야 하면 기존 컨트롤을 새 흐름 어디에 쓰는지 보여 준다. 예를 들어 검색 패널은 기존 검색창과 결과 행을 그대로 쓰면서 선택 뒤 돌아갈 위치를 바꿀 수 있다. 프로젝트에서 컴포넌트 이름을 확인할 수 있으면 그 이름을 쓴다.

## 정보의 시각적 우선순위

- 실제에 가까운 항목 하나로 무엇을 먼저 읽어야 하는지 판단한다. 받은편지함에서는 보낸 사람과 제목, 배송 대기열에서는 문제가 생긴 배송 건과 마감 시각이 먼저 눈에 들어와야 할 수 있다. 해당 필드는 글자 스타일로 강조하고, 여러 항목에서 비교할 값은 같은 위치에 정렬한다.
- 제목, 본문, 보조 문구에는 프로젝트의 글자 스타일을 대응시킨다. 레이블과 값은 가깝게 두고 서로 다른 그룹 사이는 더 띄운다. 말줄임이나 고정 행 높이를 정하기 전에 긴 번역 문구와 확대된 글자로 확인한다.
- 강조 방식은 의미에 따라 정한다. 배경을 채운 버튼으로 다음 행동을, 계속 보이는 선택 표시로 현재 열린 항목을, 상태 문구로 오류 원인을 드러낼 수 있다. 세 표시가 한 화면에 있을 때도 구분되는지 확인한다.

이 기준은 2018년 *Material Design*의 “The type system”, “Spacing methods”, “Applying color to UI”를 참고했다. 실제 수치는 대상 제품의 토큰과 플랫폼 단위로 정한다. 과거의 치수와 제스처는 당시 기기와 버전의 사례로 다룬다.

## 상호작용 선택

- 기기마다 레이아웃이나 입력 방식이 달라지면 [탐색과 입력](references/navigation-and-input-ko.md)을 참고해 계속 보여 줄 정보, 기능에 접근하는 방법, 돌아갈 위치를 정한다.
- 데이터가 바뀌거나 외부 서비스의 응답이 필요한 기능은 [피드백과 복구](references/feedback-and-recovery-ko.md)를 참고해 처리 중 상태, 결과, 제품이 실제로 지원하는 다음 행동을 설계한다.
- 속성 패널을 열어 둔 채 작업하거나 여러 객체를 함께 편집하는 화면은 [데스크톱 편집](references/desktop-editing-ko.md)을 참고한다.
- 펜 입력, 시계에서 휴대폰으로 이어지는 작업, 공용 테이블, 헤드셋 입력은 [기기별 상호작용](references/device-interactions-ko.md)에서 해당 하드웨어 부분을 읽는다.

시대별 시각 스타일이나 충실한 복원, 제품 스타일 가이드를 요청하면 설치된 경우 `ui-style-direction`을 사용한다. 여기서 설계한 작업 흐름으로 그 스타일을 확인한다.

대상 기기의 입력 방식으로 핵심 작업을 따라가고 설계가 달라질 만한 상황 하나를 확인한다. 프로토타입에서는 상태 전환을 보여 준다. 설계안에서는 사용자가 무엇을 보고 어떤 행동을 할 수 있는지 설명한다.
