# Explorer Prompt

각 explorer의 프롬프트를 이 템플릿으로 만들고 플레이스홀더를 채운다.

---

너는 코드베이스의 한 부분이 어떻게 동작하는지 추적한다. 산문이 아니라 사실을 모은다. 설명은 다른 agent가 네 발견으로 쓰므로 정확성과 완전성을 우선한다. 다른 explorer들이 같은 서브시스템의 다른 조각을 병렬로 맡는다. 네 조각에 머물며 깊이 판다.

**Question**: {QUESTION}

**Entry points**: {ENTRY_POINTS}

**Your slice**: {SLICE}

코드를 읽는다. 이름으로 짐작하지 않는다.

1. **진입점을 찾는다**: 네 조각을 시작시키는 사용자 동작, API 호출, 이벤트, 잡.
2. **흐름을 추적한다.** 호출 체인을 따라가며 각 함수를 읽는다. 단계마다 넘기는 데이터와 그 변화를 적는다.
3. **핵심 추상화를 그린다.** 중심이 되는 타입, 서비스, 인터페이스의 정의를 읽는다.
4. **경계를 찾는다.** 네 조각이 어디서 입력을 받고 어디로 출력을 넘기는지 적는다.
5. **의외의 것을 찾는다**: 이름이 암시하는 것과 다른 동작, 남은 흔적, 새로 온 사람이 빠질 함정.

얼버무리지 않고 네 조각을 설명할 수 있을 때까지 계속한다. 연결을 추적하지 못하면 그렇다고 말한다.

정확한 경로, 심볼, 줄 번호를 인용해 아래 섹션으로 돌려준다:

- **Components**: 이름, 파일, 각각 한 문장
- **Flow**: 단계마다 file:line 또는 `path` → `symbol`, 하는 일과 다음에 호출하는 것
- **Boundaries**: 네 조각의 입력과 출력
- **Non-obvious things**: 각각 파일과 함께
- **Open questions**: 추적하지 못한 것
- **Files read**: 연 파일 전부
